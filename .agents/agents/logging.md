# Logging rules (info-mfss / Django / Structlog / stdlib)

## Стек и архитектура

- Формат: структурные логи через structlog (или stdlib logging с JSON-форматтером).
- Конфигурация: настраивается централизованно через словарь LOGGING в settings.py.
- Пакетный менеджер: библиотеки логирования ставятся строго через Poetry (poetry add structlog).

## Правила написания логов

- Категорически запрещён print() для логирования. Отладка — через breakpoint(), постоянные записи — через logger.info(...).
- Использовать kwargs вместо f-строк в тексте сообщения. Строка события должна оставаться константной для корректной группировки в ELK/Loki:

 # Плохо: динамическая строка
 logger.info(f"Схема подстанции {substation_id} сгенерирована за {duration}с")

 # Отлично: константное событие + параметры
 logger.info("substation_layout_generated", substation_id=substation_id, duration_s=duration)

- Никогда не логировать секреты. Пароли, токены, API-ключи, cookies и ПДн запрещено передавать в kwargs. Параметры вида password=... или token=... — критический дефект.
- Не логировать внутри горячих циклов, чтобы не создавать I/O bottleneck. Логируй итог или сэмплируй.
- Сквозной request_id прокидывается через Django Middleware и автоматически прикрепляется ко всем логам HTTP-запроса.

## Уровни логирования

- debug: подробная локальная отладка (в проде выключено).
- info: ключевые бизнес-события и успешные операции.
- warning: нештатная ситуация, успешно обработанная кодом (retry, fallback).
- error: ошибка выполнения операции, требует анализа (с exc_info=True).
- critical: отказ сервиса или базы данных.

В проде базовый уровень — INFO и выше; DEBUG включается через LOG_LEVEL=DEBUG.

## Запреты (блокируют merge)

- print() в кодовой базе infoMFSS/.
- f-строки внутри текста сообщения логгера.
- Поля password, token, secret, authorization в kwargs логгера.
- Вызовы logging.basicConfig(...) в обход settings.LOGGING.
