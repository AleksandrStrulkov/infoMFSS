Структура тестовой директории:
- tests/tests_deploy/ — критически важные, стабильные регрессионные и интеграционные тесты для продакшна/деплоя.
- tests/test_temporary/ — быстрые смоук-тесты, проверки гипотез, отладка промежуточных функций и черновики на время активной разработки фичи.

Правила работы с тестами:

1. Определение зоны ответственности:
 - Если пишется черновик, проверяется локальный парсер, единичный эндпоинт или промежуточный вывод: создавай файл в tests/test_temporary/ (например, test_127v_quick.py).
 - Если функциональность завершена, протестирована и готова к коммиту: оформляй постоянный тест в tests/tests_deploy/ с корректными TestCase-классами Django и изоляцией данных.

2. Запуск тестов (строго внутри контейнера):
 - Запуск временных тестов:
 docker compose exec web python manage.py test tests.test_temporary
 - Запуск постоянных тестов:
 docker compose exec web python manage.py test tests.tests_deploy
 - Запуск конкретного файла:
 docker compose exec web python manage.py test tests.test_temporary.test_127v_quick

3. Жизненный цикл тестов:
 - Не оставляй временные тесты висеть навсегда. Как только фича стабилизирована, переноси ценные проверки из tests/test_temporary/ в tests/tests_deploy/.
 - Мусорные и одноразовые тесты-прогоны после успешной стабилизации удаляй или запрашивай подтверждение на очистку.
 - Перед переносом в tests_deploy убедись, что тест проходит повторный запуск на чистой тестовой базе без сайд-эффектов.
