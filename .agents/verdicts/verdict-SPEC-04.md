## 2. Оценка по 5-пунктной рубрике
1. Соответствие контракту (скоуп спеки): **PASS** — `RegisterView.dispatch` ставит `Referrer-Policy: same-origin` и сохраняет `Cache-Control: private, no-store` для действительного и недействительного приглашения. Обновлены ожидания ответов, в том числе конкурентного погашения. Django Client с `enforce_csrf_checks=True` получает HTTPS-страницу, cookie и CSRF-токен из HTML-формы; HTTPS POST с same-origin `Referer` без `Origin` возвращает 302, создаёт и аутентифицирует одного пользователя, погашает приглашение. Отдельный HTTPS POST с действительной CSRF-парой без `Referer`/`Origin` возвращает 403 без побочных эффектов. Это интеграционная симуляция Django Client, не браузерный E2E.
2. Доказательства качества (Quality Gate): **ISOLATED_PASS** — повторный `poetry run gate`: exit 1 на первом этапе Ruff; **не `gate == 0`**, последующие этапы внутри gate не запускались. Повторно: Ruff check и format для двух изменённых файлов — exit 0; `docker compose exec -T web pytest -q tests/tests_deploy --no-cov` — 34 passed, exit 0. Повторная отдельная проверка basedpyright двух файлов — exit 1, 67 ошибок, 0 предупреждений; независимое сопоставление Ревьюера подтверждает совпадение каждой из 67 ошибок с базой `bb3c6a6` (70 ошибок), новых диагностик нет. Это дельта новых ошибок 0, а не зелёный basedpyright.
