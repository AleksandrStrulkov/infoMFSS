# SPEC-01: Страница схем электроснабжения 127 В

## 1. Цель
Открывать существующий интерфейс инженерных схем из карточки «Схемы электроснабжения 127В» на главной странице Django по постоянному URL того же сайта. Домен публичный, поэтому JSON-схемы доступны **только после авторизации** через Django; в открытой статике находится лишь JS/CSS-движок React/Mermaid. Источник данных — `frontend/src/data/schemas/mine_N/*.json`, без переноса топологии в ORM.

## 2. Границы задачи (Scope)
- Входит:
  - Собрать React/Vite/Mermaid в публичные JS/CSS-ресурсы для Django `collectstatic` и Nginx `/static/`, **без содержимого JSON-схем в бандле или иных публичных артефактах**. Настроить детерминированные имена файлов и размещение сборки отдельно от `static_collected/`.
  - Django MTV: `mfss:power_circuit` → защищённая `LoginRequiredMixin` + `TemplateView` → шаблон-контейнер `infoMFSS/power_circuit.html`, подключающий собранные JS/CSS и монтирующий React в `#root`. Несобранный `frontend/index.html` напрямую не использовать: он ссылается на `/src/main.jsx`.
  - Добавить защищённые Django GET-эндпоинты для каталога схем и содержимого выбранной схемы. React получает каталог и текущий JSON через `fetch` на том же origin; убрать `import.meta.glob` и запросы к Vite dev API. Кнопку Upload и вызовы `/api/upload-schema` отключить/скрыть.
  - Заменить пустой `{% url  %}` в карточке [home.html](../infoMFSS/templates/infoMFSS/home.html) на `{% url 'mfss:power_circuit' %}`; добавить тесты маршрутов, доступа, ответов и сборки.
- НЕ входит:
  - Новые модели/миграции, синхронизация JSON с ORM, серверная генерация Mermaid/SVG.
  - Перенос React в Django templates, редизайн страницы или переработка SVG-алгоритмов.
  - Загрузка/редактирование схем через браузер, публичный upload, проксирование Vite dev-сервера и Node-сервер в эксплуатации. Изменения JSON выполняются в исходном каталоге при управляемом развёртывании.

## 3. Входные и выходные данные (Контракт)
- Страница: `GET /power-circuit/`, имя `mfss:power_circuit` в [infoMFSS/urls.py](../infoMFSS/urls.py); view в [infoMFSS/views.py](../infoMFSS/views.py), шаблон `infoMFSS/power_circuit.html`. Для вошедшего — `200 text/html`; для гостя — `302` на `users:login` с `next=/power-circuit/`.
- Каталог: `GET /power-circuit/schemas/`, имя `mfss:power_circuit_schemas`; только авторизованным. Ответ `200 application/json`: `{ "schemas": [{ "id": "mine_1/1-3Д Север ВПП.json", "mine": "Шахта 1", "name": "1-3Д Север ВПП" }] }`. `id` — относительный путь из утверждённого корня схем, URL-кодируется в запросе содержимого; `mine` — подпись из поля JSON `mine` либо папка `mine_N` при отсутствии; `name` — имя файла без `.json`. Каталог включает только доступные корректные JSON-файлы в каталогах `mine_N`, сортировка по папке и имени. Пустые каталоги не отображаются.
- Содержимое: `GET /power-circuit/schemas/<schema_id>/`, имя `mfss:power_circuit_schema`, где `schema_id` передаётся URL-кодированным **одним сегментом** (например, `mine_1%2F...json`); во избежание неоднозначности декодирования `%2F` прокси/сервером при реализации предпочтительно использовать два отдельных параметра URL: `GET /power-circuit/schemas/<mine_dir>/<filename>/` с `mine_dir=mine_N` и `filename=*.json`. **Контракт для реализации — именно двухсегментный вариант**, `id` из каталога разбирается клиентом на эти две части. Ответ `200 application/json` — исходный объект схемы (`mine`, `locations`, `connections_*`), без дополнительной оболочки. URL для запросов передаётся React через Django-шаблон как базовый путь `/power-circuit/schemas/`, а не определяется из текущего origin Vite.
- Для обоих JSON-эндпоинтов: гость → `302` на login; отсутствующая схема/некорректный идентификатор, включая попытки `..`, вложенные пути, не-`mine_N` и не-`.json` → `404`; неподдерживаемый метод → `405`. На успешных ответах и редиректах с JSON-эндпоинтов задать `Cache-Control: private, no-store` (не допускать хранения данных в общих кэшах). При повреждённом JSON сообщать об ошибке серверу и не раскрывать путь файловой системы в ответе; каталог не должен выдавать непригодные записи.
- Контракт сборки: Vite выдаёт только JS/CSS (и их технические ресурсы, если появятся) под `/static/...` с детерминированными именами entry/CSS/chunks; `collectstatic` переносит их в `static_collected/`. Не использовать manifest/inline-JSON/копирование каталога `schemas` в статические пути. Сборка и Docker-образ должны иметь контролируемый доступ к исходным схемам **только на стороне Django**, а не через nginx/staticfiles.
- Поведение UI: начальное состояние загрузки → список шахт/схем из каталога → загрузка выбранного JSON → `jsonToMermaid`/`postProcessMermaidSvg`; на `401/302`/ошибку JSON показывать ошибку или предлагать повторный вход, не рендерить HTML страницы входа как JSON. При переключении схем не оставлять экспорт предыдущей SVG; при пустом каталоге показать пустое состояние. Экспорт SVG/PNG/PDF/JSON остаётся клиентским после получения схемы.

## 4. Требования к данным и БД
- Затронутые модели: нет; миграции: **нет**; `select_related`/`prefetch_related` не нужны. Корень закрытого файлового каталога задаётся в `config/settings.py` настройкой `POWERCIRCUITSCHEMASDIR`: значение берётся из `os.getenv('POWERCIRCUITSCHEMASDIR')`, при отсутствии переменной — `BASE_DIR / 'frontend' / 'src' / 'data' / 'schemas'` (в запросе пользователя `BASEDIR` означает существующий в проекте `BASE_DIR`). При переопределении допускается абсолютный путь или путь относительно `BASE_DIR`; итоговый корень нормализуется до абсолютного пути. Во views и сервисе чтения схем нельзя хардкодить путь: использовать только `settings.POWERCIRCUITSCHEMASDIR`.
- В текущем compose проект целиком смонтирован в `/app`, поэтому дефолтный путь доступен backend. В production схемы доставляются одним из двух способов: копируются в образ backend через Dockerfile **или** монтируются отдельным volume в каталог, указанный `POWERCIRCUITSCHEMASDIR`; выбранный вариант должен сохранять каталог вне `STATICFILES_DIRS`/`STATIC_ROOT`, `MEDIA_ROOT` и публичных alias Nginx. При образе без общего bind mount явно обеспечить наличие исходных JSON в backend; при отдельном volume не монтировать его в Nginx.
- Защитить границу файловой системы: разрешать только папки вида `mine_[1-9][0-9]*` и конечные имена файлов `.json` без разделителей/служебных сегментов; после нормализации проверять принадлежность к корневому каталогу. Не принимать произвольные абсолютные пути и не следовать ссылкам наружу. Ограничить чтение разумным размером файла (ориентир 2 МБ на схему, как в текущем Vite dev upload); возвращать только JSON-объект, а не произвольное содержимое файла.
- Новая/исправленная JSON-схема доступна через защищённый API после обновления файлов на backend **без пересборки Vite и без `collectstatic`**. JS/CSS пересобирать только при изменении приложения. Проверить, что процесс сборки и раздачи статики не копирует JSON в открытые каталоги, а клиентские исходники не содержат встроенные схемы.

## 5. Требования к качеству (Acceptance Criteria)
- [ ] `reverse('mfss:power_circuit') == '/power-circuit/'`; карточка ссылается на этот маршрут, HTML не содержит пустого `{% url  %}` и `/src/main.jsx`.
- [ ] Гость не получает ни страницу схем, ни список/содержимое JSON; вошедший получает корректные ответы. JSON-ответы имеют `Cache-Control: private, no-store`; Nginx/staticfiles не раздают исходные схемы.
- [ ] Каталог отражает файлы `mine_N/*.json`; содержимое совпадает с исходным JSON. Проверена работа как с дефолтным `POWERCIRCUITSCHEMASDIR`, так и с временным каталогом через переопределение настройки; views не используют собственный путь к схемам. Проверены отсутствие файла, неверный идентификатор, traversal, вложенные пути/ссылки наружу, повреждённый JSON и ограничение размера; никакие ошибки не раскрывают абсолютный путь.
- [ ] После `npm run build` и `collectstatic` в `/static/` доступны JS/CSS без 404, имена файлов детерминированы; проверка содержимого/дерева сборки подтверждает отсутствие названий и содержимого приватных JSON, включая чанки, map-файлы и прочие публичные артефакты.
- [ ] React не использует `import.meta.glob`, `/api/schema-dirs`, `/api/upload-schema`; Upload скрыт/отключён, данные запрашиваются только у защищённых Django-эндпоинтов. Проверены загрузка, смена шахты/схемы, пустой каталог, ошибка/истечение сессии, обе ориентации, масштаб и экспорт.
- [ ] Django test client покрывает URL, авторизацию, каталог и выдачу файлов; frontend smoke-test проверяет загрузку и отсутствие dev API. N+1 не возникает: ORM-запросы для схем не используются.
- [ ] При реализации кода выполнить проектный gate по [AGENTS.md](../AGENTS.md), зафиксировать результат и заполнить `reviews/handoff-01.md`. Пока согласуется спецификация, код и тесты не меняются и gate не запускается.

## 6. План реализации
1. Добавить `POWERCIRCUITSCHEMASDIR` в `config/settings.py` с чтением из окружения и дефолтом `BASE_DIR / 'frontend' / 'src' / 'data' / 'schemas'`. На стороне Django читать схемы только через эту настройку; проверить текущий compose bind mount и два допустимых способа доставки в production — `COPY` в backend-образ либо отдельный volume по пути настройки, без доступа Nginx/staticfiles. Зафиксировать проверки путей, размера и JSON, политику `no-store`.
2. Настроить Vite для сборки **только движка** в исходный каталог Django staticfiles с base `/static/...` и детерминированными именами; убрать импорт схем в JS и исключить схемы из всех публичных артефактов. Закрепить порядок `npm run build` → `collectstatic`; Node в текущем Dockerfile не установлен.
3. Реализовать Django view для страницы и две защищённые JSON-view (каталог/содержимое), именованные маршруты; передать React базовый API-путь через шаблон. Привязать карточку в `home.html`.
4. Перевести React на загрузку списка и выбранной схемы через Django, убрать dev API и Upload, обработать пустые данные, ошибки и истечение сессии; сохранить существующий рендер и экспорт.
5. Добавить тесты доступа и безопасной работы с файлами, frontend smoke-test и проверку отсутствия JSON в сборке; выполнить quality gate и оформить handoff.

**Спецификация согласована.** JSON схем не публикуется в `/static/` ни прямо, ни внутри JS/CSS/чанков/карт исходников; доступ к данным — только через Django после авторизации. Путь задаёт `settings.POWERCIRCUITSCHEMASDIR` с дефолтом внутри `BASE_DIR`; доставка в production — копирование схем в backend-образ или отдельный volume по этому пути, без публичной раздачи. Конкретный способ выбирается при развёртывании.
