# Анализ структуры моделей и связей

## 🔴 Критические проблемы

### 1. Неправильный default в ForeignKey (Tunnel.inclined_blocks)
**Местоположение:** `models.py:79`
```python
inclined_blocks = models.ForeignKey(
    InclinedBlocks,
    ...
    default="Туффит",  # ❌ ОШИБКА: default должен быть объектом или callable, а не строкой
)
```
**Проблема:** ForeignKey не может иметь строковое значение по умолчанию. Это вызовет ошибку при создании миграций или при сохранении объектов.

**Решение:**
```python
# Вариант 1: Убрать default, оставить только nullable
inclined_blocks = models.ForeignKey(..., **NULLABLE)

# Вариант 2: Использовать callable
def get_default_inclined_block():
    return InclinedBlocks.objects.get_or_create(title="Туффит")[0]

inclined_blocks = models.ForeignKey(..., default=get_default_inclined_block, **NULLABLE)
```

### 2. Потенциальная ошибка в CableMagazine.save()
**Местоположение:** `models.py:361`
```python
def save(self, *args, **kwargs):
    self.name = f"{self.track_from.name}/{self.track_to.name}"  # ❌ Может упасть если track_from или track_to = None
```
**Проблема:** Если `track_from` или `track_to` равны `None` (а они nullable), произойдет `AttributeError`.

**Решение:**
```python
def save(self, *args, **kwargs):
    if self.track_from and self.track_to:
        self.name = f"{self.track_from.name}/{self.track_to.name}"
    elif self.track_from:
        self.name = f"{self.track_from.name}/?"
    elif self.track_to:
        self.name = f"?/{self.track_to.name}"
    else:
        self.name = "?/?"
    super().save(*args, **kwargs)
```

### 3. Хардкод подсистемы в EquipmentInstallation.save()
**Местоположение:** `models.py:460`
```python
self.subsystem = Subsystem.objects.get(title="АТС")  # ❌ Может упасть если нет такой подсистемы
```
**Проблема:** Если в БД нет подсистемы с title="АТС", возникнет `DoesNotExist`.

```python
try:

    # Или создать:
    # self.subsystem = Subsystem.objects.get_or_create(title="АТС")[0]
```

### 4. Проблема с unique полями в Beacon
**Местоположение:** `models.py:650-652`
```python
mac_address = models.CharField(max_length=17, verbose_name="MAC-адрес", unique=True, default="")
serial_number = models.CharField(max_length=10, verbose_name="Зав. №", unique=True, default="")
minor = models.CharField(max_length=10, verbose_name="МИНОР", unique=True, default="")
```
**Проблема:** Поля с `unique=True` и `default=""` могут вызвать проблемы, если создать несколько записей без указания значений - все будут иметь пустую строку, что нарушит уникальность.

**Решение:**
```python
# Вариант 1: Убрать default, сделать nullable
mac_address = models.CharField(..., unique=True, **NULLABLE)

# Вариант 2: Использовать null=True вместо default=""
mac_address = models.CharField(..., unique=True, null=True, blank=True)
```

## ⚠️ Проблемы с целостностью данных

### 5. Execution может быть пустым
**Местоположение:** `models.py:491-504`
```python
equipment_install = models.ForeignKey(..., **NULLABLE)
cable_magazine = models.ForeignKey(..., **NULLABLE)
```
**Проблема:** Оба поля nullable, значит Execution может быть создан без связи ни с оборудованием, ни с кабелем. Это логически некорректно.

**Решение:**
```python
# Добавить валидацию в clean() или save()
def clean(self):
    if not self.equipment_install and not self.cable_magazine:
        raise ValidationError("Должна быть указана либо установка оборудования, либо трасса кабеля")
```

### 6. Visual может быть полностью пустым
**Местоположение:** `models.py:590-601`
```python
number_mine = models.ForeignKey(..., **NULLABLE)
subsystem = models.ForeignKey(..., **NULLABLE)
equipment = models.ForeignKey(..., **NULLABLE)
cable = models.ForeignKey(..., **NULLABLE)
```
**Проблема:** Все FK nullable, значит можно создать Visual без какой-либо информации.

**Решение:**
```python
def clean(self):
    if not any([self.number_mine, self.subsystem, self.equipment, self.cable]):
        raise ValidationError("Должен быть указан хотя бы один параметр")
```

### 7. Несогласованность типов данных в Beacon
**Местоположение:** `models.py:627`
```python
subsystem = models.CharField(max_length=20, verbose_name="Подсистема", default="Позиционирование")
```
**Проблема:** В других моделях `subsystem` - это ForeignKey к модели Subsystem, а здесь - CharField. Это нарушает нормализацию данных.

**Решение:**
```python
subsystem = models.ForeignKey(
    Subsystem,
    related_name="beacon_subsystems",
    on_delete=models.CASCADE,
    verbose_name="Подсистема",
    **NULLABLE
)
```

## 📊 Проблемы с производительностью

### 9. Отсутствие индексов на часто используемых полях

**Проблема:** Нет явных индексов на полях, которые часто используются в фильтрах:
- `NumberMine.title` - используется во всех фильтрах
- `Subsystem.title` - используется в фильтрах
- `Execution.execution_bool` - используется в базовых фильтрах
- `EquipmentInstallation.number_mine`, `subsystem`, `inclined_blocks` - часто в JOIN'ах

**Решение:**
```python
class NumberMine(models.Model):
    title = models.CharField(max_length=15, verbose_name="Шахта", choices=NAME, db_index=True)
    
class Execution(models.Model):
    execution_bool = models.BooleanField(..., db_index=True)
    
class EquipmentInstallation(models.Model):
    class Meta:
        indexes = [
            models.Index(fields=['number_mine', 'subsystem']),
            models.Index(fields=['inclined_blocks']),
        ]
```

### 10. Множественные nullable ForeignKey

**Проблема:** Много nullable FK может усложнить запросы и снизить производительность.

**Статус:** ⚠️ **Приемлемо**, но стоит рассмотреть возможность нормализации или использования полиморфных связей для некоторых случаев.
